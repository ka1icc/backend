## Формулировка задания

Даны два XML-файла — ответы на запросы к API партнёра Via.com:

- `RS_Via-3.xml` — ответ на запрос «туда-обратно» (round-trip);
- `RS_ViaOW.xml` — ответ на запрос «в одну сторону» (one-way).

**Требовалось:**

1. Распарсить оба файла.
2. Вывести **списком** отличия между результатами двух запросов по маршрутам (тег `Flights`).
3. По каждому маршруту указать:
   - какие рейсы входят в маршрут;
   - время начала и время конца маршрута;
   - цену маршрута;
   - что изменилось по условиям?
   - добавился ли новый маршрут?

## Что я сделала в проекте

- Выбрала **FastAPI** как веб-фреймворк и **SQLAlchemy 2.0** как ORM для работы с **PostgreSQL**.
- Спроектировала три таблицы: загрузка XML-ответа (`xml_responses`), маршрут (`routes`), сегмент рейса (`flight_segments`). Парсер читает XML и заполняет эти таблицы.
- Логику сравнения вынесла в отдельный модуль: строю ключ маршрута по цепочке рейсов «туда», определяю новые маршруты, исчезнувшие и общие; для общих — что изменилось (цена, время, тип маршрута RT/OW).
- Сделала веб-страницу (Jinja2 + Bootstrap 5): кнопка «Загрузить XML-данные», после загрузки — сводка и раскрывающиеся блоки по разделам задания (новые маршруты, только в первом ответе, общие с отличиями). Плюс JSON API `/api/compare` для программного доступа.
- Настроила линтер (flake8 + wemake-python-styleguide) и isort в `setup.cfg`.
- Добавила Docker: `Dockerfile` и `docker-compose.yml` (сервисы `db` и `web`), скрипты `deploy.bat` и `deploy.sh` для автоматического развёртывания.
- Оставила отдельный CLI-скрипт `compare_via_routes.py` — он парсит XML без БД и пишет текстовый отчёт в файл.
